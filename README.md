# AI Finance Controller — Reconciliation + GST Exception Checker

**Track:** AI Finance Controller
**Focus:** Closes one finance-ops loop across a batch of merchant transactions —
catches settlement mismatches *and* GST misclassification in a single pass.

## The problem

Every month, finance teams at merchants manually do two separate, tedious checks:

1. **Reconciliation** — does every sale in our books have a matching settlement
   from the bank/payment gateway? Same amount, same date, same reference?
2. **GST classification** — was the correct GST rate applied on each sale? Item
   descriptions are messy free text, and misclassification is a common, costly
   mistake (e.g. packaged drinking water is often wrongly marked exempt when it's
   actually 18%).

Both are usually done by hand, by people, once a month, on spreadsheets. This tool
does both automatically on a batch of transactions and outputs a single exception
report with an estimated rupee amount at risk.

## Architecture

```
bank_statement.csv  ─┐
                      ├─▶  Reconciliation engine (deterministic, rule-based)
merchant_ledger.csv ─┤        matches by reference → checks amount & date
                      │
                      └─▶  GST classification engine (AI-assisted)
                              reads item_description → predicts category
                              via Claude → looks up correct rate from a
                              fixed table → compares to rate actually applied
                                    │
                                    ▼
                         exception_report.csv
                    (per-transaction flags + total money at risk)
```

**Why AI is used only in one place:** matching two records or comparing two
numbers doesn't need a language model — it needs to be exactly right, every
time, so that part is plain deterministic code. The one place a model earns
its keep is reading a messy, free-text item description and mapping it to a
tax category. The GST *rate* itself always comes from a fixed lookup table,
never from the model — so even if the model misreads a description, it can't
invent a tax rate that doesn't exist.

## What broke, and how it was fixed

The offline fallback classifier (used when no API key is set) matches item
descriptions against a keyword list. Any description that doesn't hit a
keyword — e.g. "Handcrafted ceramic vase" — was returned as `"Uncategorised"`
with `rate = None`. Downstream, the script tried to compute
`abs(correct_rate - applied_rate)` to estimate money at risk, which crashed
with a `TypeError` on `None - int`.

**Fix:** the money-at-risk calculation now only runs when a rate was actually
resolved; unclassifiable items are still flagged as GST exceptions (so nothing
is silently dropped) but are excluded from the rupee estimate rather than
crashing the whole run. This is also the strongest argument for running with
a real API key rather than the fallback in production — a proper LLM call
handles unfamiliar descriptions far better than a fixed keyword list ever
will.

## Running it

```bash
pip install -r requirements.txt

# Optional: for real AI-based GST classification instead of the offline
# keyword fallback, set your API key first
export ANTHROPIC_API_KEY=your_key_here

python3 generate_data.py   # (re)generates the synthetic transaction batch
python3 main.py            # runs both checks, writes exception_report.csv
```

## Output

Console summary: total transactions checked, reconciliation exception count,
GST exception count, and estimated total rupees at risk.

`exception_report.csv`: one row per transaction with both check results side
by side — `reconciled` / `reco_reason` and `predicted_gst_category` /
`applied_gst_rate` / `correct_gst_rate` / `gst_ok`.

## Data

`bank_statement.csv` and `merchant_ledger.csv` are synthetic (58 transactions,
generated by `generate_data.py` with a fixed seed) — built to include a
realistic mix of clean transactions, missing settlements, amount/date
mismatches, and GST misclassifications, so the checks have real things to
catch.

GST rates used are illustrative slabs for demo purposes and should be
verified against current official GST notifications before any real use.
